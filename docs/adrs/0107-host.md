# ADR-0107 — The host serves one project to the people its invite admits, with the person's pi setup, streams in the document, and a store

- **Status:** Accepted
- **Area:** `apps/pinetrie/host/TECHNICAL.md`, `packages/schema/TECHNICAL.md`
- **Evidence:** S22, S23, S53, S108, S112
- **Supersedes:**
  - ADR-0022: restated whole, with ADR-0023, ADR-0032, ADR-0042, ADR-0044 and
    ADR-0086 folded in.

Restates ADR-0022 as amended by ADR-0023, ADR-0032, ADR-0042, ADR-0044 and
ADR-0086, and by S112; decides nothing new. Where the agent's tools run is
ADR-0034's, as amended by ADR-0102 and ADR-0103: in a lane of its own. How
the session's documents are cut is ADR-0063's.

**Context.** The walking skeleton ran a host with no project, no
admission and no models of the person's own. To be used on real work it
needs a repo to serve, a way to let collaborators in and keep others out,
the models the person already configured for pi, and somewhere to keep the
session across restarts.

**Decision.**

- **The host serves one project.** By default it is the repo the host runs
  from; `pnpm host <folder>` names another (ADR-0086, S108). Every thread's
  agent works on it in a lane of its own, never in the project's working
  copy (ADR-0032, ADR-0034, ADR-0102). The agent's tools are on by default;
  `PINETRIE_TOOLS=0` turns them off. A host started from code (`startHost`)
  has none unless given a project, so no suite runs commands by accident.
- **Loopback by default; an invite key anywhere else.** The host binds to
  `127.0.0.1` unless `PINETRIE_BIND` says otherwise. Off loopback, nothing
  gets in without the key: no page, no file, no WebSocket, Vite's socket
  included (S112). The key comes as an invite link (`?key=`), which sets an
  `HttpOnly` cookie and redirects to the page without it. A request whose
  `Origin` names another host is refused, key or no key, and a loopback host
  refuses a `Host` that is not a loopback name (ADR-0042). Three limits:
  - the key decides who gets in, not who is who: a person is the email
    their client names (ADR-0037), unverified;
  - the key crosses a network in the clear, which a trusted network or a
    tunnel allows and the open internet does not, without a TLS proxy;
  - with tools on, anyone with the link can have the agent run commands, and
    the host says so at startup.
- **Models come from the person's pi setup.** pi's own `SettingsManager`
  and `DefaultResourceLoader` load the person's packages, and only the
  extensions' provider registrations are applied to pine·trie's
  `ModelRuntime`. The settings' default model is used unless
  `PINETRIE_PROVIDER` and `PINETRIE_MODEL` override it. The system prompt is
  pi's `buildSystemPrompt`, with the project's `AGENTS.md` and the person's
  skills. Suites never use this: they name their model, or script one.
- **Replies and tool output are one kind of stream, written as text
  edits.** A stream is a record (`streams`) and a text (`streamText`), keyed
  by a fresh id. A reply's stream opens on its message's first text, a
  tool's with the tool, and a stream goes once its entry is written, so the
  screen hands over from the stream to the entry without a gap (ADR-0044).
  A tool's output arrives as snapshots of a tail-kept view and is written
  with `tailEdit`; pi's own tool-output checkpoints are stored the same way
  (`checkpointText`).
- **A stop control** ends a thread's running turn; what waits for the lane
  then goes as usual.
- **The session persists** in a Kyneta SQLite store over `node:sqlite`
  (`.pinetrie/pinetrie.db` by default), as JSON compacted when every run
  ends (ADR-0023). A starting host clears every stream and run.

**Consequences.**

- While a tool runs, its output is in the document twice, as the live
  stream and as pi's checkpoint; compaction clears both when the run ends.
  They could share one text if pi's `tool_update` carried the checkpoint's
  key: an upstream request.
- A collaborator can pose as another person: per-person invites are later
  work.
- The person's pi setup is pine·trie's: a provider the person adds to pi
  reaches pine·trie with no setting of its own.

**Alternatives rejected.**

- **A second checkout for the agent, beside the host's own code.** Lanes
  give each thread's agent its own copy (ADR-0034); the host needs none.
- **Admission by loopback alone.** Multiplayer needs a network address, and
  reaching the port must not be enough: whoever does gets the session, the
  page's source and the command channel.
- **A login.** The invite link is enough for a trusted group, and identity
  is the email a client names (ADR-0037).
- **Models configured for pine·trie alone.** The person would configure
  every provider twice.
- **Streams written as whole snapshots.** Every snapshot of a long tool's
  output would grow the document; a tail edit writes only what changed.
