# ADR-0106 — An ask is a message and the run it started; the column folds the agent's part, and a long ask is digested

- **Status:** Accepted
- **Area:** `docs/06-interface.md`, `packages/interface/TECHNICAL.md`
- **Evidence:** S21, S59, S70, S99, S101, S105
- **Supersedes:**
  - ADR-0056: restated whole, with ADR-0048 (step 7), ADR-0070, ADR-0071,
    ADR-0072, ADR-0075, ADR-0077 and ADR-0082 folded in.
  - ADR-0070: its one change, the last word in outline, is stated here.
- **Amended by:**
  - ADR-0126: a run has an ask, the message that started it; who stopped a run
    is a fact in its thread, not a `pinetrie.stop` record.
  - ADR-0173: an ask's digest is drawn as one summary row, at one place, at
    every density, never in a fold's head.

Restates ADR-0056 as amended by ADR-0048 (step 7), ADR-0070, ADR-0071,
ADR-0072, ADR-0075, ADR-0077 and ADR-0082; decides nothing new. ADR-0056's
changes to ADR-0031 (stretches) and ADR-0054 (the working mark names the
ask) stand as ADR-0056 made them.

**Context.** A thread with an agent in it is mostly the agent's work: its
messages and tool rows between one person's request and the next. Read in
full, a long thread buries what was asked and what came of it; folded by
length alone, a fold could cross from one request into the next, or hide a
branch. A run is the agent's work for one message (`planChat` holds every
message for a busy lane, and `promptOf` relies on it, S21), so the unit to
fold and to summarize is that message and its run.

**Decision.**

- **An ask is a message that started a run, together with that run.** The
  message can be anyone's, a catch-up's or a split's included; a message
  for people only is not an ask. A carry-on message, written when someone
  resumes after a Stop, starts an ask, and names who resumed (ADR-0082).
  Asks are derived from the tree by a pure function in `packages/core`, and
  never stored. The running ask is the `promptOf` of a running lane's tip.
- **The column never folds a person's message. It folds the agent's part
  of a run.** A landmark inside the run splits the fold: a fork, the first
  message of a branch, a running tip, an open column's end, or the end of
  someone's thread. Each landmark is drawn as itself, so a fold hides
  content, never structure.
- **The rail draws the same stretches, coarser.** An ask whose run holds at
  least `MIN_STRETCH` (3) agent messages is a long ask: a landmark, whose
  run is a stretch of its own. Short asks and messages between people merge
  as ADR-0031 has it. The rail may merge folds but never split one; the
  column may open a fold but never merge two. A capsule's tooltip leads with
  its ask.
- **A column is read at one of three densities, which the reader chooses:**

  | density | a finished ask shows |
  |---|---|
  | **outline** | its message, one line (its outcome, and its last word), and its digest under it |
  | **story** | its message, its fold line led by the digest's headline, and its last word |
  | **raw** | every message and tool row |

  A message for people only shows at every density. A new column opens in
  story. A column's density is kept with it in the tab's layout, and only
  the reader changes it.
- **An ask's outcome is a value, read from its run's last entries:**
  answered, stopped (an `aborted` stop reason, or a tool result cancelled)
  or failed (an `error` stop reason). A restart does not end a run: pi
  resumes it from the same prompt (S70). A stopped ask has no final reply,
  and its line says who stopped it.
- **A stop is recorded under its ask.** When Stop aborts a run, the host
  writes `pinetrie.stop`, keyed by the ask's entry, with who pressed it and
  when, before it asks pi to abort; the first written stands. A Stop while
  a message card is queued also holds the thread's queue, so the run's end
  sends nothing until someone releases it (ADR-0048, step 7).
- **A reader opens or closes any ask's fold, at any density,** and the
  column remembers it. Anything that brings a message into view opens the
  fold holding it, decided by one function.
- **The running ask is open in story and raw.** It folds once its run has
  ended and the column is at its end, unless the reader opened it, so the
  column never shortens during a run (ADR-0044). In outline it is one line
  that pulses, showing the running command or the agent's latest text.
- **The ask stays in sight while its work scrolls.** A bar laid over the
  column's top names the ask whose work is at the top; a column starting
  inside a run sticks `↰ answering Ada: "…"`. This takes up ADR-0028's
  sticky section header for asks; a mark's, when built, sticks above it.
- **The fold line is counted from the run's entries:** the agent's
  messages, tool calls, the files its turns changed, its time, and failed
  calls.
- **An ask's files are the diff across its run's revisions.** After each
  agent message that changed files, the host commits a revision and records
  it under the entry (`pinetrie.revision`), with the paths it changed, read
  with jj, since git reads a conflicted commit as every side's tree, and
  with the commit's conflicts (ADR-0072, S99). A press on the count opens
  the review pane on the range from the ask's prompt's commit to its last
  turn's.
- **A long ask has a digest written by a model** (ADR-0071, ADR-0075). It
  is on by default; `{ "digests": { "enabled": false } }` in the user
  config turns it off. The request is made outside the thread, under the
  replaceable `ask-digest` skill, and only for a long ask. Its reply is a
  headline of at most 14 words and at most four points, or `nothing to
  add`; the host reads it before writing it (`digestOf`), refuses any other
  shape, and never cuts one. `pinetrie.digest` holds `{ headline, points,
  at, final }`, refreshed at most once per interval while someone reads the
  thread, and once more at the run's end. It is drawn as a model's words,
  apart from the agent's, and no agent reads it.
- **A run's end asks for a verdict, digests on or off** (ADR-0077): one
  request returns the verdict first and, for a long ask, the final digest
  (`endReplyOf`).
- **"Since you were here" marks where you left off,** read from your
  attention document's `read`, the furthest entry you have read in each
  lane, so it is the same on every device of yours (ADR-0077, S101). Read
  in story, what lies below the line is the catch-up.

**Consequences.**

- One segmentation in `packages/core` decides the column's folds and the
  rail's stretches, so the two cannot disagree about what is hidden. Its
  property tests check that no stretch crosses an ask and every landmark
  stays drawn.
- The rail grows by one dot and one capsule per long ask, and your own
  messages can be found on it.
- In story and outline a finished ask draws one line in place of its rows,
  which makes long threads cheaper to render (S59).
- The browser's find cannot see text inside a closed fold.
- Every run's end costs one model request, for its verdict; a long ask's
  also writes its digest, and a running long ask costs one request per
  interval while someone reads it.

**Alternatives rejected.**

- **Folding by length, or by time.** A fold could cross from one ask into
  the next, or hide a fork.
- **Folding a person's message with the work.** The ask is what a reader
  scans for.
- **A digest of every ask.** A short ask's last message says what it came
  to; asking a model for it costs a request and adds nothing (ADR-0075).
- **A digest the agent writes in the thread.** It would sit in the
  thread's context and history.
- **Cutting a reply that runs long.** A cut list says something the model
  did not.
- **"Since you were here" per device.** You would see the same catch-up
  again on every device.
